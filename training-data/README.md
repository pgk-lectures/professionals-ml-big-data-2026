# Тренировочные данные

Эти данные подготовлены специально для обучения по модулю А и дальнейшего перехода к модулям анализа и машинного обучения.

## Важно

- это **не официальные данные чемпионата**;
- маршруты синтетические, но используют реалистичные географические координаты;
- использовать их для реальной навигации нельзя;
- поле `cadence` добавлено искусственно, потому что частота шагов требуется критериями;
- набор предназначен для обучения механике задания, а не для получения реальных выводов о безопасности маршрутов.

## Состав

`tracks.json` имитирует список ссылок на маршруты.

В наборе:

- **12 маршрутов** с `source=provided` — имитация исходных данных от организаторов;
- **8 маршрутов** с `source=additional` — имитация треков, найденных на туристических платформах;
- **20 маршрутов всего**;
- **15 GPS-точек в каждом маршруте**;
- около **300 строк** после формирования итогового датасета;
- 4 региона;
- все четыре сезона;
- несколько повторяющихся типов маршрутов в разные сезоны.

URL в `tracks.json` указывают на raw-файлы этого же репозитория, поэтому загрузчик действительно получает GPX по HTTP, а не читает их напрямую из локальной папки.

## Почему данных стало больше

Первоначальные 6 маршрутов по 8 точек давали только **48 строк**. Этого достаточно, чтобы показать сам pipeline модуля А, но слишком мало для нормальной тренировки следующих частей задания.

Новый набор специально увеличен, чтобы после модуля А на нём можно было:

- строить сезонную и региональную аналитику;
- выполнять кластеризацию;
- формировать учебные метки риска;
- делить данные на train/test;
- сравнивать несколько классических ML-моделей.

## Хватит ли этого для машинного обучения

Для **учебной задачи** — да. Примерно 300 наблюдений достаточно, чтобы пройти весь процесс классификации и сравнения моделей на Scikit-learn.

Для реального ML-проекта — нет. Набор синтетический и слишком небольшой, чтобы делать практические выводы о реальной безопасности туристических маршрутов.

Отдельно: прогноз на 10 лет из модуля В потребует исторической временной серии погодных и природных данных. Её нужно будет собирать отдельно при разборе этого модуля.
